The Correction Slip

A machine-readable correction protocol. When a fact changes, ONE slip propagates to every agent that cited the old version, with the retraction on the record.

Honest label: this is a tamper-evident hash chain, not cryptographic signing. CWI holds no signing keys and invents none. Each slip embeds the SHA-256 of the previous slip; verification = recompute the chain.

Live chain files

  • slip-schema.json — the slip schema
  • chain.json — the ordered seed chain (real CWI corrections)
  • subscribers.json — agent/document fact subscriptions (SAMPLE seed)

Slip fields

slip_id, issued_at, issuer_urn, fact_id, supersedes, superseded_text, corrected_claim, retraction_note, affected_citations, prev_hash, slip_hash, schema_version

Commands (stdlib Python)

python3 slip.py issue --chain-dir slips --roster roster.json \
  --issuer-urn agent:CWI_Data --fact-id fact-<id> \
  --supersedes <old-claim-id> --superseded-text "<old>" \
  --corrected-claim "<new>" --retraction-note "<note>" \
  --citations "agent:CWI_Data,agent:CWI_Press"

python3 slip.py verify --chain-dir slips --roster roster.json
python3 slip.py check --chain-dir slips --fact-id fact-<id>
python3 slip.py propagate --chain-dir slips --subscribers subscribers.json --fact-id fact-<id>

Design lineage (studied, not endorsed)

  • Crossref Crossmark: a uniform status-check button on every record; corrections/retractions linked bidirectionally to the original; originals flagged, never silently amended; machine-readable updates via REST API.
  • Certificate Transparency: append-only log, publicly auditable, the log itself untrusted but verifiable by anyone — the honest-authority model this chain copies.
  • Scholarly corrections practice: neutral, fact-focused retraction language; originals retained with prominent flags; metadata updated and reindexed.
